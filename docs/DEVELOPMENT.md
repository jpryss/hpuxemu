# hpuxemu — notes for developers

This file is for working on the emulator: the layout, how to rebuild and test, and how
to debug a program that does not run. Users want [GETTING_STARTED.md](GETTING_STARTED.md)
and the [README](../README.md); how it works is [DESIGN.md](DESIGN.md), the interface as
a specification [ABI.md](ABI.md) and [SYSCALLS.md](SYSCALLS.md), the CPU
[CPU.md](CPU.md).

## 1. Layout

    rust/hpuxemu/   the emulator (DESIGN.md §10): src/main.rs (the command line),
                    process.rs, loader.rs, som.rs, kernel.rs (the run loop), signals.rs,
                    threads.rs, streams.rs, netman.rs, owners.rs, host.rs, stats.rs and
                    syscalls/{files,proc,mmap,ioctl,net,ipc,misc}.rs; consts.rs is
                    GENERATED by tools/genrust.py from the Python constants
    rust/hppa32-jit/  the CPU crate, a submodule (github.com/jpryss/hppa32-jit): the
                    interpreter, the x86-64 JIT, the address space, the C interface
    hpuxemu/
      emu.py        the Python emulator, the reference: Process (loader, state, 220
                    sys_* handlers, signals, credentials and permission checks, the
                    process table), main()
      lwp.py, streams.py, netman.py, native.py   kernel threads, STREAMS devices, the
                    MIB devices, the natively run routines of dld.sl and libc
      cpu.py        the reference PA-RISC interpreter: Memory, Cpu, op_* methods
      rustcpu.py    the Rust CPU behind the same interface, through ctypes
      decode.py     the decoder (shared by cpu.py, disasm.py and the fuzzer)
      disasm.py     a disassembler in gas syntax; `python3 -m hpuxemu.disasm FILE [ADDR [N]]`
      som.py        the SOM object format; `python3 -m hpuxemu.som -s|-d FILE`
      iso9660.py    an ISO 9660 reader (HP's directory-size quirk included)
      depot.py      SD-UX depots: directory depots on a CD, serial (tar) depots, CRC
                    checks, fileset extraction; `python3 -m hpuxemu.depot`
      mkroot.py     installs filesets, applies patches, post-processes the root
      adopt.py      a root from a machine's tar/cpio archive
      owners.py     the root's owners table; rootdir.py: where the root is by default
      consts.py, consts11.py, scall11.py   GENERATED from the root's /usr/include
                    (tools/genconsts.py, genscall11.py): constants, system call and
                    signal names, structure sizes and offsets - do not edit
    kernel/         the STREAMS daemon (DESIGN.md §8), K&R C for HP's bundled cc: strd.c
                    (the framework, stream heads, the server), timod.c, dlpi.c, inet.c
                    (TCP and UDP as TPI providers), ksubr.s (the kernel's setjmp)
    build.py        the root builder; data/filesets.txt what it takes, data/media.sha256
    tools/
      emucmd.py     the emulator's command line for the tools: the Rust emulator when
                    it is built ($HPUXEMU names another; HPUXEMU=python the Python one)
      sweep.py      runs tools/sweep.txt (sweep11.txt: 11.00 only) through the emulator;
                    --cpu all compares the Rust emulator with the Python one, --cpu
                    both the Python emulator's two CPUs
      ptytest.py    drives an interactive shell on a pty: job control, signals
      ctest.py      random K&R C programs: HP's cc in the emulator against the host's gcc
      telnettest.py logs in through inetd/telnetd and checks who -mR
      xstub.py, xdrive.py, pcffont.py  the stub X server, its control-socket client,
                    PCF fonts; xtest.py (xclock, xterm) and cdetest.py (a CDE session,
                    a front panel click) run against it
      census.py     starts every program of a root once -> docs/COMPAT.md
      fuzz.py       the differential CPU fuzzer (CPU.md §2); nativetest.py compares the
                    natively run routines with the real code
      test_decode.py  the decoder against the GNU assembler's test suite
      hpdisk.py, swinstall.py, mkstrd.py, mdf2iso.py, mkroot.sh, cde-wsl.sh, stats.py
                    the user's tools (README)
      genconsts.py, genscall11.py, genrust.py, syscalls_doc.py   the generators
    examples/       the C programs the sweep compiles with HP's cc

## 2. Rebuilding and testing

    (cd rust/hpuxemu && cargo build --release)      # the emulator (and the CPU crate)
    (cd rust/hppa32-jit && cargo build --release --features capi,hpux)   # the CPU as a library: for the Python emulator and the fuzzer
    python3 build.py --patches --scripts core.iso enhance.iso   # a root
    python3 tools/genconsts.py                      # only after changing the struct list (needs the root and gcc)
    python3 tools/genrust.py                        # after genconsts.py: the same for Rust
    python3 tools/syscalls_doc.py > docs/SYSCALLS.md

The tests, all against a real root (there is no mock HP-UX):

    python3 tools/fuzz.py -n 100000 -j 2            # the CPUs against each other (2 min)
    python3 tools/sweep.py                          # 66 commands on the emulator (7 s)
    python3 tools/sweep.py --cpu all                # each on the Python emulator too, compared
    HPUXEMU_JIT=0,64 python3 tools/sweep.py         # everything compiled at once: the JIT's hard setting
    python3 tools/sweep.py -r ../hpuxroot11 tools/sweep11.txt
    python3 tools/ptytest.py                        # an interactive sh on a pty
    python3 tools/xtest.py                          # xclock and xterm against the stub X server
    python3 tools/cdetest.py                        # a CDE session: ttsession, dtwm, dtfile, dthelpview, a front panel click -> dtpad (2 min)
    python3 tools/telnettest.py -s                  # portmap + inetd, a telnet login (port 23: needs root or a redirect)
    python3 tools/census.py -r COPY-OF-ROOT > docs/COMPAT.md   # every program once; on a copy
    python3 tools/ctest.py -n 12 --lines 4000       # random K&R C: HP's cc + the CPU against the host's cc (10 min)
    (cd rust/hppa32-jit && cargo test --release)    # the CPU crate's own tests, no root needed

A change to the CPU wants a million fuzz sequences to agree; a change to the OS layer
the sweep (`--cpu all`: the two emulators agree), the pty test and the X tests. A
system call is changed in both emulators, the Python one first where the question is
what HP-UX does: it is the quicker place to find out. Add a line to `tools/sweep.txt`
for every program that newly works (with `=> expected text`; `~` in front when its
output varies between runs).

There is no CI with a root: a root is HP's software and stays on its user's machine.
What can run without one - the builds, the decoder test, the fuzzer, the generated
files being current - is what `.github/workflows/ci.yml` runs.

## 3. Debugging a program

1. `-t` traces every system call with its arguments and result, as `tusc` would:
   `hpuxemu -t /usr/bin/prog 2>&1 | less`. Paths are shown as strings; `-- signal X
   delivered` and `-- sigcleanup` lines mark signal frames. `HPUXEMU_TRACE=NAME` traces
   only the processes running a program of that name, each into
   `$HPUXEMU_TRACE_DIR/NAME.PID` (default `/tmp`): one daemon among dozens.
2. A crash prints the registers, pc and the instruction count; `python3 -m hpuxemu.disasm
   FILE ADDR` disassembles around the pc (for a shared library, subtract where it was
   mapped - the `mmap` lines of the trace - and add 0x1000).
3. `HPUXEMU_HOOKS=addr,addr,...` prints the registers each time execution reaches an
   address (and what r26-r23 point at); the program keeps running. `HPUXEMU_TRACE_PC=1`
   with `-t` adds each system call's stub and caller, which finds the code behind a
   call quickly; symbols (`python3 -m hpuxemu.som -s FILE`) name it in libraries that
   keep them (dld.sl does).
4. `HPUXEMU_JIT=off` runs the interpreter alone, `HPUXEMU_FASTMEM=0` makes compiled
   loads check the page flags, `HPUXEMU_NATIVE=0` runs dld.sl's and libc's own code
   instead of the native routines: three switches that tell whether the CPU's fast
   paths have a part in a failure.
5. The same program on the Python emulator (`python3 -m hpuxemu.emu --cpu rust`) tells
   whether the two emulators differ - compare the two `-t` traces, which have one
   format; `--cpu python` there tells whether the CPUs differ (they should not; if they
   do, `tools/fuzz.py --only CLASS` on the suspect instruction class).
6. Unknown ioctls and system calls print `hpuxemu: ... unimplemented` with the number;
   `consts.py` names it (`SYSCALL_NAMES[n]`, or `grep` the ioctl value in `C`).
7. `HPUXEMU_STATS=FILE` and `tools/stats.py` say where the time went (BENCHMARK.md).

## 4. Conventions

- Every `sys_*` handler of the Python emulator has a docstring: SYSCALLS.md is generated
  from them.
- No numbers typed from memory: structure offsets, flags, errnos and signal numbers
  come from `consts.py`, i.e. from HP's headers. When a header is missing a fact, the
  behaviour is observed and the finding written into ABI.md.
- Documentation describes the program as it is, with measured numbers and the machine
  they were measured on.
- Nothing from the media, no root, no host names or personal data in the repository,
  in the test files or in the documents.
